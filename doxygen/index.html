Linux on Serverless

A real Linux kernel, compiled to WebAssembly, running inside one Cloudflare Worker. Each machine is a Durable Object with a BusyBox userland and a browser terminal.

🎯 Why gmux

Serverless platforms run functions, not machines. gmux runs the machine: Linux 7.0 boots to a shell inside a Durable Object, and ordinary Linux programs run on it unmodified, with processes, pipes, job control, signals, threads, sockets, fork and dlopen. A job that needs more CPU than one event allows continues across events. The host can turn a running machine into bytes (Machine.checkpoint) and resume it exactly in a fresh isolate (Machine.restore).

🚀 Quick Start

Run a machine locally with Docker:

docker run --rm -p 8787:8787 ghcr.io/gmitch215/gmux

Open http://localhost:8787/_gmux/term, claim the machine, and you are at a root shell. The container's /var/lib/gmux volume holds the machine's Durable Object storage.

Deploy your own to Cloudflare:

git clone https://github.com/gmitch215/gmux && cd gmux
bun install --ignore-scripts
bun run hydrate # the released kernel build
bash scripts/build-assets.sh # the terminal page
bunx wrangler deploy

The first visitor to /_gmux/term claims the machine and receives its owner token.

📥 Install the Library

The machine host is an npm package with the kernel, BusyBox, Katybug and the initramfs inside it:

bun add @gmitch215/gmux
import { createHash } from 'node:crypto';
import { Machine } from '@gmitch215/gmux';
import manifest from '@gmitch215/gmux/kernel/manifest.json';
import vmlinux from '@gmitch215/gmux/kernel/vmlinux.wasm';
import busybox from '@gmitch215/gmux/kernel/busybox.wasm';
import initrd from '@gmitch215/gmux/kernel/initramfs.bin';
const machine = new Machine({
vmlinux,
initrd: new Uint8Array(initrd),
cmdline: 'maxcpus=3 root=/dev/ram0 rootfstype=ramfs init=/init console=hvc',
registry: new Map([[manifest.busybox, busybox]]),
sharedKernel: true,
sha256: (bytes) => createHash('sha256').update(bytes).digest('hex'),
write: (text) => console.log(text)
});
machine.type('uname -a\n');
const started = Date.now();
await machine.run(
() => Date.now() - started > 5_000,
(ms) => new Promise((resolve) => setTimeout(resolve, ms))
);

The host runs in a Durable Object, workerd, or Node with JSPI (WebAssembly.Suspending). In a Worker, .wasm imports compile at deploy time, which is the only place a Worker may compile code.

🐧 What Runs

Userland BusyBox, with an interactive shell, pipelines and job control
Processes fork, vfork, execve, pthreads, signals with handlers that block
System sockets (Unix and loopback TCP), epoll, eventfd, timerfd, inotify, flock, System V IPC
Libraries dlopen of wasm side modules shipped with the deployment
Foreign binaries unchanged x86-64 and AArch64 Linux ELFs, through Katybug

Programs are compiled for wasm32-linux with scripts/cc-strict, which refuses any import outside the syscall surface. Code that arrives at run time cannot be compiled on Workers, so every native executable is built with the deployment.

🐞 Katybug

Katybug runs unmodified x86-64 and AArch64 Linux executables inside a machine. It ships in the package as kernel/katybug.wasm, an ordinary gmux program: it decodes the guest's machine code into gmux's IR, runs it, and turns each guest syscall into the machine's own. The init script registers it with binfmt_misc, so a shell, execve and fork treat a foreign ELF like any other program.

  • Executables: static and dynamically linked, against glibc or musl with their own ld.so
  • Processes: fork, execve, threads, signals and their handlers
  • Instruction sets: x86-64 with x87 and SSE, AArch64 with its floating point and SIMD
  • Host implementations: recognized library code (the string functions, zlib, the md5, sha1, sha256 and sha512 blocks) runs on host kernels, and a whole md5, sha1, sha256 or sha512 stream can finish on the host's own crypto
  • Images: an executable's pages are read from its file when first touched

Running a Foreign Binary

Register Katybug next to BusyBox, then add the executable to the root filesystem by appending a newc cpio archive to the initramfs. The kernel unpacks the archives in order.

printf 'hello\n' | cpio -o -H newc > hello.cpio
import { createHash } from 'node:crypto';
import { readFileSync } from 'node:fs';
import { Machine } from '@gmitch215/gmux';
import manifest from '@gmitch215/gmux/kernel/manifest.json';
import vmlinux from '@gmitch215/gmux/kernel/vmlinux.wasm';
import busybox from '@gmitch215/gmux/kernel/busybox.wasm';
import katybug from '@gmitch215/gmux/kernel/katybug.wasm';
import initrd from '@gmitch215/gmux/kernel/initramfs.bin';
const base = new Uint8Array(initrd);
const extra = readFileSync('hello.cpio');
const pad = (4 - (base.length % 4)) % 4;
const image = new Uint8Array(base.length + pad + extra.length);
image.set(base);
image.set(extra, base.length + pad);
const machine = new Machine({
vmlinux,
initrd: image,
cmdline: 'maxcpus=3 root=/dev/ram0 rootfstype=ramfs init=/init console=hvc',
registry: new Map([
[manifest.busybox, busybox],
[manifest.katybug, katybug]
]),
sharedKernel: true,
sha256: (bytes) => createHash('sha256').update(bytes).digest('hex'),
digest: (algorithm) => createHash(algorithm),
write: (text) => console.log(text)
});
machine.type('/hello\n');
const started = Date.now();
await machine.run(
() => Date.now() - started > 10_000,
(ms) => new Promise((resolve) => setTimeout(resolve, ms))
);

digest is optional. With it, a digest stream Katybug recognizes runs on the host's crypto; without it, Katybug hashes with its own kernels. A machine cannot checkpoint while a host digest is open.

The technical report's Foreign Executables section covers how Katybug decodes, caches and lifts code, its host kernels, and what each costs.

🧱 How It Works

The kernel and every process share one WebAssembly memory. A syscall is a direct call from the program's instance into the kernel's. Blocking is JSPI: every task that waits is a suspended wasm stack, and one pump on the Durable Object's single thread resumes exactly the task the kernel schedules next. When a machine has to leave memory, its parked stacks become bytes (Asyncify for the kernel, resumable frames or Asyncify for programs), and a restore rewinds them into fresh instances. Foreign executables run through Katybug.

TECHNICAL_REPORT.md has the design, the platform limits that shape it, and what each operation costs.

🔒 Security

A machine is a Durable Object: code inside it has no Worker bindings, secrets or network authority beyond what the host passes to it, and a deployed Worker cannot compile code at run time. Inside one machine, root processes share one trust domain; a non-root process reaches only its own memory and the shared mappings it maps, and a forked process runs in a memory of its own. SECURITY.md has the trust model, the import surface and the threat matrix.

🛠️ Building from Source

The kernel, musl, BusyBox and Katybug build reproducibly on a Linux host with Docker from the pins in src/sources.json and the patches under src/:

scripts/build-linux.sh ~/gmux-build # the toolchain, kernel, libc, userland and probes
scripts/build-kernel.sh ~/gmux-build/out # staged into build/
bun run test:probes # C probes booted in a machine

Two clean builds produce the same bytes in every artifact. The probes refuse a build/kernel staged from other pins or patches than the tree's.

The kernel, LLVM and linux-wasm forks are fetched from mirrors listed in src/mirrors.json, so a build does not depend on their authors keeping them online. bun scripts/sync-mirrors.ts reports new and moved branches and checks that every pinned commit is on its mirror; --apply copies the new and moved branches to the mirrors with a gh login that can write to them.

bun run typecheck
bun run test
bun run format:check
